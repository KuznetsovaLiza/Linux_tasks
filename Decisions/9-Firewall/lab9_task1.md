2. Проверьте осталась ли возможность подключения по ssh к вашему серверу

    ```bash
    [elizabeth@host-15 ~]$ ssh student@ternar.io -p 224
    Last login: Mon Dec 29 13:10:19 2025 from 94.180.38.175
    [student@S-vm-224 ~]$ 
    ```

3. Почему может пропасть такая возможность?

    После установки iptables все цепочки (chains) по умолчанию имеют политику ACCEPT, но если ранее были настроены правила или после установки были применены правила, блокирующие все входящие подключения, SSH соединение может быть потеряно.

4. Откройте нужный порт на сервере чтобы восстановить подключение

    ```bash
    [student@S-vm-224 ~]$ sudo iptables -A INPUT -p tcp --dport 224 -j ACCEPT
    ```

    - Проверка:

    ```bash
    [student@S-vm-224 ~]$ sudo iptables -L
    Chain INPUT (policy ACCEPT)
    target     prot opt source               destination         
    ACCEPT     tcp  --  anywhere             anywhere             tcp dpt:224

    Chain FORWARD (policy ACCEPT)
    target     prot opt source               destination         

    Chain OUTPUT (policy ACCEPT)
    target     prot opt source               destination         
    ```

5. Это будет udp или tcp прот?

    TCP, так как SSH использует TCP протокол

6. Сохраняются ли записанные вами правила после перезагрузки?

    Нет, правила iptables не сохраняются автоматически после перезагрузки. Их нужно явно сохранять.

7. Как их сохранить?

    ```bash
    [student@S-vm-224 ~]$ sudo iptables-save | sudo tee /etc/sysconfig/iptables
    # Generated by iptables-save v1.8.10 on Mon Dec 29 14:09:56 2025
    *filter
    :INPUT ACCEPT [9076:786568]
    :FORWARD ACCEPT [0:0]
    :OUTPUT ACCEPT [8788:882684]
    -A INPUT -p tcp -m tcp --dport 224 -j ACCEPT
    COMMIT
    # Completed on Mon Dec 29 14:09:56 2025
    ```
